PROJECT OVERVIEW
================================================================================
A web tracking data quality monitoring dashboard built with:
- React + TypeScript
- react-router (NOT react-router-dom)
- motion/react for animations
- lucide-react for icons
- Tailwind CSS v4
- recharts for data visualization

PURPOSE: Monitor data quality across web tracking events (GA4) and marketing 
platforms (Meta CAPI, Google Ads) with drill-down functionality.

================================================================================

1. WEB TRACKING QUALITY SECTION
   - Overall Health Score (visual indicator)
   - Insights Panel (showing missing parameters)
   - Client/Server Discrepancy Cards (Sessions, Purchases)

     * session_start

RECENT CHANGES - META CAPI PLATFORM DETAIL PAGE
================================================================================

PARAMETER CATEGORIZATION UPDATE
We reorganized Meta CAPI parameters based on their actual business impact:

CRITICAL PARAMETERS (4 total) - Technical Requirements
These are REQUIRED for Meta to accept/process the event:
  ✓ event_id - UUID/ULID for Pixel/CAPI deduplication (92.3%)
  ✓ event_name - Must match Meta's standard naming (100%)
  ✓ event_time - Unix timestamp, loses power after 1 hour (100%)
  ✓ action_source - Where event occurred (website/app/store) (100%)

WARNING PARAMETERS (6 total) - Event Match Quality (EMQ) Boosters
Missing these won't break the connection but will tank EMQ score and ad performance:
  ⚠ user_data.em - Hashed Email, highest-priority matching key (87.3%)
  ⚠ user_data.ph - Hashed Phone, high-priority identifier (82.1%)
  ⚠ user_data.fbc - Click ID from fbclid, Meta ad clicks only (76.5%)
  ⚠ user_data.fbp - Browser ID, unique browser identifier (94.2%)
  ⚠ user_data.client_ip_address - User differentiation in server-to-server (99.8%)
  ⚠ user_data.client_user_agent - User differentiation in server-to-server (99.9%)

OPTIONAL PARAMETERS (10 total) - Business/E-commerce Data
Critical for ROAS optimization but optional for basic attribution:
  • custom_data.value - Required for Purchase events ROAS calculation (92.7%)
  • custom_data.currency - Required for Purchase events ROAS (98.4%)
  • custom_data.content_ids - Required for Dynamic Product Ads (88.6%)
  • custom_data.content_type - Required for Dynamic Product Ads (85.3%)
  • user_data.fn - First name, optional matching (68.4%)
  • user_data.ln - Last name, optional matching (67.9%)
  • user_data.ct - City, optional matching (45.3%)
  • user_data.st - State, optional matching (41.7%)
  • user_data.zp - Zipcode, optional matching (58.2%)
  • user_data.country - Country, optional matching (89.1%)

Each parameter now includes:
- eventsWithParam count
- eventsMissing count
- percentage (completion rate)
- description (explaining business impact)

CHART UPDATES - ERROR RATE VISUALIZATION
================================================================================

BOTH Meta CAPI and Google Ads platform detail pages now show:

"Error Rate Trends by Category" Chart
- Y-axis: "% Missing" (showing error percentage, not quality percentage)
- X-axis: Last 7 days (dates)
- Three lines tracking error rates over time:
  🔴 Critical Errors - Average % of missing critical parameters
  🟠 Warning Errors - Average % of missing warning parameters
  ⚫ Optional Errors - Average % of missing optional parameters

CALCULATION LOGIC:
- Error percentage = 100 - completion percentage
- For each category, we average the error rates across all parameters in that category
- Time series adds realistic variation (±1%) around the average

NAVIGATION STRUCTURE
================================================================================

Routes (using react-router):
  / → Dashboard (main view)
  /event/:eventName → EventDetail (web tracking drill-down)
  /platform/:platformId → PlatformDetail (marketing platform drill-down)

Navigation Flow:
1. User sees Dashboard with both sections
2. Click on event scorecard → Navigate to /event/session_start (etc.)
3. Click on platform scorecard → Navigate to /platform/meta-capi or /platform/google-ads
4. Platform detail shows parameter breakdown + error trend chart
5. "Back to Dashboard" button returns to /

IMPORTANT TECHNICAL NOTES
================================================================================

⚠ USE react-router, NOT react-router-dom
   - Import from 'react-router' only
   - react-router-dom does not work in this environment

⚠ USE motion/react for animations
   - Import: import { motion } from 'motion/react'
   - This is the new Motion library (formerly Framer Motion)

⚠ Tailwind CSS v4
   - Theme tokens in /src/styles/theme.css
   - No tailwind.config.js needed

⚠ Recharts Best Practices
   - Always provide unique keys for Line components
   - Add unique id field to data points when needed
   - Use ResponsiveContainer for proper responsive behavior
